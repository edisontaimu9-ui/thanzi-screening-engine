## Objective
Give the team an evidence pack and a deployment package for v0.7.0: what was tested and how, what was not, and what Hope needs to deploy safely behind her gateway. ## Hard rules
- Phases 1-6 are tested and packaged, not changed. Any defect found is reported and decided in the log before a fix.
- No invented clinical thresholds or expected values. Expected results in any test pack come from the approved rules (R3 pages cited), and Maria confirms or disputes them.
- Synthetic data only. No real patient data.
- Every new tool is recorded in the register (version, licence, intended use) before use. Dev and CI tools only; the runtime image gains no new dependency.
- Nothing is called "validated" or "load tested" unless it was run, and the run is stated with its environment.

## Deliverables
**A. Test evidence**
1. `docs/testing/traceability.md` (generated by `scripts/build_traceability.py`): rule registry entry, source and page, test ids, for every CMAM rule. Fails if a rule has no test.
2. Coverage report in CI with a floor (Q3). Coverage numbers are reported as measured; I will not set a target I have not seen.
3. Boundary and property tests where the engine has monotonic or symmetric behaviour (for example, a lower weight never lowers risk). Stdlib-only; `hypothesis` is not proposed.
4. End-to-end case pack `docs/testing/case-pack.xlsx` for Maria: inputs, engine classification, rule and page cited, blank columns for her agreement and comment. Generated from the engine, so it shows what the engine does, not what is clinically right.
5. WHO Anthro cross-check (I5) if the output is supplied (Q7).

**B. Non-functional**
6. `scripts/load_probe.py` (stdlib): latency percentiles and error counts for `POST /v1/screen` at stated concurrency, run against a local container with memory and CPU limits. Results recorded with the environment.
7. Robustness: malformed and oversized input, wrong content types, and degraded mode through the container.
8. Startup time, image size, memory at rest, recorded.

**C. Security**
9. CI: `pip-audit`, Trivy image scan, `gitleaks`, SBOM artifact. Findings triaged in the log; no silent ignores.
10. Constraints file for transitive dependencies (Q4), so builds and the OpenAPI check are reproducible.
11. Test that captured container logs contain no request body and no key values.

**D. CI hardening** (from the findings above): stronger smoke assertions (expected class, worker view has no `hiv`, audit view works only with both keys, 401 and 403 cases, healthcheck reaches `healthy`), job timeouts, concurrency, pip cache, Dependabot for Actions and pip, SHA pinning of Actions (Q1).

**E. Release and deployment package**
12. `docs/deployment/runbook.md` for Hope: environment variables, key generation and rotation, network isolation (I21), health monitoring, rollback, what the service does not do (TLS, rate limits, audit logging).
13. `deploy/docker-compose.example.yml`: private network, no published port, secrets from files. Example only; Hope's setup governs.
14. Release workflow: tag `v0.7.0`, build image, attach SBOM and test report. Publishing to a registry only if Q6 says so.
15. `docs/testing/test-report.md`: what was run, environment, results, and a plain list of what was not tested.
16. Sign-off checklist listing open clinical and data items (I10, I12, I13, I18, I19, I23, I24, I25) with owners.
